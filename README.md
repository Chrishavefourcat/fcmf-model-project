# 模型评级系统

当前版本从 Python 源码启动本地网页，使用系统浏览器完成模型评级。运行需要 Python 3.10+、浏览器，以及 `requirements.txt` 中的 SQLAlchemy 和 openpyxl；SQLite 随 Python 提供，无需另装数据库服务。

Windows 10 / 11 双击 `start.bat`，或在项目目录执行 `powershell -File .\start.ps1`。脚本先检查已有 Python 3.10+，包括 PATH 和标准安装目录的注册信息；找不到可用解释器时，自动从 Python 官方下载完整 Python 3.14.10，校验 SHA256 后解压到当前用户的 `%LOCALAPPDATA%\ModelRatingSystem\python\` 缓存目录。此过程无需管理员权限，不修改系统 PATH 或覆盖已有 Python。

随后脚本创建项目内的 `.venv`、安装 `requirements.txt` 依赖、启动服务并打开默认浏览器。首次下载需要能访问 python.org 和 Python 包安装源，网络失败时保留错误提示，可再次运行重试。以后启动会复用环境，仅在依赖清单变化或环境不完整时安装依赖，环境齐备后可以离线运行。Python 运行时及依赖仍不随源码压缩包分发。自动下载已在 Windows x64 验证，x86 / ARM64 有对应下载配置但尚未实机验证。

接收方可将 [启动依赖与Agent操作清单.md](启动依赖与Agent操作清单.md) 交给自己的 agent，按清单安装环境并启动。本应用只需 Python、浏览器及 Python 库，无需 Node.js。依赖固定为支持 Python 3.10 的 `SQLAlchemy==2.0.57` 和 `openpyxl==3.1.5`；启动时会验证实际导入及固定版本。仅安装和校验环境可执行 `powershell -File .\start.ps1 -CheckOnly`，首次指定 Python 可加 `-Python "C:\实际Python目录\python.exe"`。

如需禁止自动下载 Python，使用 `powershell -File .\start.ps1 -NoAutoPython -CheckOnly`；该选项仍允许复用已有环境和已准备好的 Python 缓存。已有 `.venv` 若来自其他电脑或已损坏，先改名保留再重建。手动安装的 Python 需要包含 sqlite3、venv 和 ensurepip。

自动准备 Python、再次启动及 `start.bat` 的实际接口验证范围见 [Windows启动验证记录.md](Windows启动验证记录.md)。

Linux 可在项目目录运行 `sh start.sh`，先安装并检查环境用 `sh start.sh --check-only`，无桌面环境用 `sh start.sh --no-browser --port 0`；首次指定解释器用 `PYTHON=/usr/bin/python3.12 sh start.sh --check-only`。Linux 版要求 Python 3.10+、pip、venv 和 Python 自带的 sqlite3；Debian/Ubuntu 可能需要另装匹配的 `python3-venv` 包。现有文件/文件夹“浏览”弹窗仅适用于 Windows，Linux 请直接输入模型路径，或使用 `--models /实际模型路径`。macOS 可按相同命令尝试，但尚未实测。

Linux 验证已覆盖 Alpine 3.20.10 / Python 3.12.13，以及 Ubuntu 22.04.5 用户空间 / Python 3.10.12，两套环境各通过 79 项测试并完成启动、模型评分及 Excel 接口往返检查。具体环境、方法和未覆盖范围见 [Linux兼容性验证记录.md](Linux兼容性验证记录.md)。

启动后默认读取项目 `models/` 中的 SQLite 模型文件。第一步点击模型选择框右侧的“数据源选择”，在弹窗中输入本机模型文件夹或单个 `.db` 文件路径，也可点击输入框右侧“浏览…”选择“选择文件夹”或“选择 DB 文件”，通过 Windows 系统对话框回填路径，再点“使用此数据源”确认加载。随后选择模型和样本。Excel 导出使用浏览器下载，导入在页面中选择文件。

浏览器关闭标签页后，Python 服务仍会运行。在启动脚本的终端按 `Ctrl+C` 停止服务；重开页面时请使用终端打印的完整地址（含会话参数）。页面录入值只保存在当前页面，关闭或刷新前请导出需要保留的数据。

界面默认采用紧凑布局，主体跟随浏览器可用宽度铺开，没有居中的最大宽度限制。步骤与翻页按钮合并在同一栏，操作按钮、表格行和列间距压缩；桌面端表格使用剩余屏幕高度，在表格内部滚动并固定表头和主体列。窄窗口可横向滚动步骤栏和数据表，当前步骤自动保持可见；小窗口或较大缩放时也可滚动整页。长列名、主体名称和计算异常提示支持悬停查看完整内容。

## 模型数据库

- 一个模型对应一个 SQLite `.db` 文件，例如 `河南城投2026.db`。数据源为文件夹时，读取当前层级的全部 `.db` 文件；数据源为单个 `.db` 时，只加载该文件，即使同目录另有模型文件。文件名不需要以 `_model` 结尾，扩展名不区分大小写。
- 数据库须包含同结构的 `model`、`company`、`field`、`field_value`、`indicator`、`grade` 表。
- 模型选择下拉框仅显示实际 `.db` 文件名（含扩展名），按文件名排序，悬停显示完整路径。列表扫描只校验模型文件，不读取 `model.model_name`；选中后仍按文件标识读取评分数据，基准年份取该文件 `model` 表最新记录的 `base_year`。右上角数据库名称与路径同步显示当前实际文件。
- 文件夹数据源中新增模型文件后，刷新页面即可发现模型，无需改代码或重启服务；单文件数据源始终只加载指定文件。
- 切换模型会清空当前页面的样本、录入值和评分结果；查询、维护、评分以及 Excel 导入导出均使用所选数据库。
- 等级映射读取所选库的 `grade` 表。

确认切换数据源后会清空旧模型列表、当前样本和页面录入结果，下拉框只保留新数据源的模型；旧列表请求延迟返回时不会覆盖新数据源。取消浏览或浏览失败时保留原输入和原数据源，路径加载失败也保留原数据源。浏览使用轻量 Windows 系统对话框，仅回填本机路径，不上传或复制文件；业务直接读取或维护原文件，不增加 Qt 或打包依赖。SQLite 模式不需要用户名或密码，用户需有模型文件的读写权限。评分预览和 Excel 导入仅改变页面数据，数据维护接口会写入对应 SQLite 文件。

服务仅监听本机 `127.0.0.1`，默认端口 `8765`。端口被占用时会提示更换端口或先停止已有服务。启动时传入的数据源路径或环境变量只用于本次服务；页面切换的数据源路径保存在内存中。

## 原定级与第二步数据录入

第一步“原定级”从 `field_value` 读取 `field_id = 'original_grade'`，按公司和所选日期匹配，无该日期记录时回退未标日期记录，缺失留空。

第二步从全部 `indicator.expression` 提取直接引用的已定义 `field_id`，忽略字符串、函数常量等；无表达式时使用指标绑定字段。按指标现有顺序及字段首次出现顺序排列，例如 a、b、指标 A；共享源数据全局去重。源数据值来自公司、字段、所选日期对应的 `field_value`；普通字段无对应日期记录时回退未标日期记录，排查字段严格匹配所选日期。

页面默认隐藏指标列，“展示指标 / 隐藏指标”可切换；指标表头和数据格为蓝色，悬停显示计算表达式。指标计算值采用模型评分引擎计算结果（乘权重前），跟随页面修改或导入的源数据更新。源数据修改弹窗只编辑源数据。

第二步点击源数据列头的中文名称，可打开“按列修改”弹窗，列出当前已选的全部公司，分别编辑同一个字段；行内“排查”继续用于修改单家公司的多个字段。列编辑保存时仅更新实际改动的公司，未改动的值保留原始精度，空白与零值分别处理；按当前页面公式重新计算相关指标及评级，并同步后续页面和导出。取消不保存；计算请求失败时保留弹窗输入供重试。列编辑仅修改当前页面，不写入数据库。

第三、四步每个指标或排查项最上方的名称也可点击。第三步弹窗同时编辑“指标值、赋分、得分”，修改指标值时预览公式结果，修改赋分或得分时按当前权重联动，并沿用评分上下限；第四步同时编辑“指标值、得分”，修改指标值时按公式预览，手动得分优先，之后再改指标值则恢复公式计算。弹窗始终列出全部已选公司，不受表格筛选条件影响。预览不改变页面数据，保存时统一提交实际改动，其他指标的手动评分继续保留；未改动的值保留原始精度，取消丢弃修改，保存失败可重试。确认后同步更新后续评级、筛选排序和导出。

第二步主体名称、源数据和蓝色指标列的表头右下角有排序筛选图标。展开后可升序、降序、恢复原顺序，搜索并勾选筛选值，也支持全选、反选、重复项、唯一项和清除此列筛选。选项旁显示当前其他列条件下的公司数量，多列筛选叠加生效；空白与真实零值分开列出，数字按原始精度排序，空白排在末尾。搜索时空格分隔的关键词按任一匹配处理，点“确定”按匹配结果筛选；取消、Esc 或点击外部放弃未确认的勾选。

第三步主体名称、初评得分、初评等级，以及每个指标的“指标值、赋分、得分”均支持相同的排序筛选。第四步支持主体名称和各排查项的“指标值、得分”；第五步支持主体名称、债券代码、各项得分、初评等级、最终等级、人工标识和评级说明。各步骤独立保存条件，来回切换时保留；修改指标值或手动评分后按最新页面数据筛选排序，正在编辑时保留输入焦点，离开表格后更新显示顺序。

第二至第五步工具栏显示可见公司数量，并可一键“清除排序和筛选”。条件仅影响所在步骤的表格显示，不移除评级样本、不修改字段值；整列编辑仍列出全部已选公司，各步 Excel 导出和后续评级仍使用全部已选样本及原样本顺序。切换模型、数据源、数据日期或第二步重置数据库数据时清除各步骤条件，第四步重置排查数据时清除该步条件。

第二步 Excel 始终导出源数据及每个指标的“指标值”，不包含“赋分”和“得分”；指标值与页面共用显示值（包含四位小数的显示精度），隐藏指标时仍完整导出，按页面同样顺序交错排列，并以蓝色区分指标列。每个指标表头添加 Excel 批注，内容为当前生效的表达式；表达式为空时使用绑定字段。“指标信息”工作表列出指标 ID、名称、当前权重、表达式和关联字段。隐藏的第二行使用带 `indicator:` 前缀的指标标识，防止指标 ID 与字段 ID 相同导致导入混淆。

第二步导入按主体 ID、字段 ID 回填当前已选样本的源数据，零值和空白也会回填。每次成功导入都会重新请求指标计算，即使重复导入同一份文件、源数据没有发生变化，也按当前页面生效的公式重新计算；Excel 中的指标值列作为展示快照，不覆盖计算结果，旧模板的得分列不作为输入。新计算值供第二步展示和导出、后续指标得分及等级计算使用，均只保存在当前页面，不写入数据库；第五步排查得分采用第四步各项“得分”的总和。刷新、关闭页面、切换模型/数据源/日期或第二步重置会清除导入值。手动修改源数据或指标表达式后重新计算指标值，单独修改权重时重新计算得分。第四步修改、导入或重置排查数据时重新计算排查指标。

第二步“展示指标 / 隐藏指标”按钮右侧显示当前所选样本、当前日期的计算异常提示：`(指标：xx、yy 公式无法计算)`。未能得到有效数值的指标按指标 ID 去重，正常零值不提示；提示不受指标列显示开关影响，重新计算成功或移除对应样本后自动清除，只显示在页面中。

## 当前页面评分规则

第三步每个指标的“指标值”可直接修改，绑定到该指标的 `field_id`，修改后按当前页面公式重新计算赋分、得分、初评等级和最终定级。共享同一字段的指标会同步更新；其他主体不受影响。修改仅保存于当前页面，并同步用于数据导出。

第三、四步指标值均优先显示当前页面录入值，否则显示数据库字段值；没有数据时保持空白，不填充默认值或 0.0000，数据库真实的零值仍显示 0.0000。清空指标值后输入框继续为空。评分引擎的缺失值、默认值及公式规则继续生效，输入框空白与计算结果为零可同时存在。

第三步“评分规则配置”展示序号、指标名称、指标权重、指标取值公式、操作五列。点击“编辑”仅可修改权重和表达式；操作列的“取消编辑”下方有“确定”，点击即可保存当前行并立即重新评分，窗口保持打开。取消编辑恢复该行上次确认的值，底部“确定”可提交其他未确认修改并关闭窗口。表达式会校验语法、字段及函数，非法修改不生效。

规则保存在当前页面的内存中，每次评分预览和第二步导出请求携带规则副本，不调用数据库修改接口，也不修改后端共享模型定义。第二步导出包含当前页面规则及对应计算结果；切换模型、数据源、关闭页面或刷新页面后恢复数据库规则，第二步“重置为数据库数据”也会清除页面规则。权重沿用模型原值，例如 0.1 表示 10%；权重为 0 时沿用原模型直接记分的行为。

## 当前页面等级规则

第三步及最终定级页面未匹配到等级时，显示红色“等级匹配异常”；修改得分或规则后重新匹配，成功时恢复正常显示。

首次进入页面、刷新或重置后，数据库原始等级规则也按配置窗口展示的完整区间匹配；分数低于首行左边界或高于末行右边界时显示异常，不再按单侧阈值匹配到某一档。后台评分接口采用相同的区间规则。

没有页面等级覆盖值时，重新评分、打开等级规则弹窗或回到浏览器标签页会重新读取数据库 grade 表，外部数据库软件已提交的修改可同步到页面。弹窗显示实际数据库文件的完整路径，便于核对数据源。已经保存到页面的临时等级规则继续优先生效；点击“读取数据库最新规则”可清除页面等级覆盖值并恢复当前数据库规则。读取失败时保留原有规则；此操作不修改源数据、评分规则或数据库文件。

第三步“等级规则配置”读取 `grade.status = '打分映射' AND inclusive = 1` 的记录，将空 threshold 视为 -99999 后升序排列。每行左边界为 threshold，右边界为下一行 threshold，末行右边界为 99999。编辑时相邻边界联动，严格校验左边界小于右边界且区间无交叉；行内“确定”或底部“确定”保存并重新计算页面等级，取消/关闭丢弃尚未确认的编辑。删除中间或末尾行时区间并入前一行，删除首行时下一行继承原左边界，至少保留一行。生效后的区间左闭右开、末行右端点包含；配置仅当前页面生效，切换模型/数据源、刷新或第二步重置后恢复数据库规则。

## 第四步批量排查

表格保留序号、主体名称，按 `field.field_type = '排查项'` 分组，每个排查项下仅显示“指标值、得分”两列，分组名称取 `field.label`。指标值读取该项 `field_id` 对应的字段值，得分按 `indicator.field_id` 关联的指标表达式 `expression` 计算，不再展示排查说明和备注。

指标值和得分均可直接编辑。指标值支持数值和文本（如 AA-），修改后实时按表达式重算；手动修改得分后优先生效，再次修改同一项指标值时清除该项手动得分并恢复公式计算，其他项的手动得分保留。得分使用表达式直接计算结果，不乘权重、不套用指标分值上下限或舍入位数；没有关联公式时使用数值指标值，无法计算时显示异常，可修正指标值、公式或手动填写得分。多个指标绑定同一字段时，按指标 ID 顺序使用第一个指标的表达式。

指标值按 `company_id + field_id + period_end` 严格匹配，不回退未标日期或其他日期记录；页面编辑/导入值优先，数据库无值或清空时显示空白。计算得分时仍沿用模型缺失值和默认值规则，不把计算默认值填入指标值输入框。指标值与手动得分按公司、字段、日期分别保存，切换日期不会串值，切回可继续使用本次页面的修改。刷新、关闭页面、切换数据源或模型后恢复数据库数据。

第四步“重置为初始数据”重新读取数据库，清除当前日期、已选样本在第二步或第四步录入、导入的排查字段值和手动得分。非排查源数据与当前页面评分规则继续生效，得分和等级重新计算；重置不写入数据库。

“导出Excel”采用两层表头：主体代码、主体名称，以及每个排查大项下的“指标值、得分”。导出与第四步表格共用页面快照，仅导出当前主体及顺序，保留当前指标值、公式得分和手动得分，不在导出时重新查询或计算。表头使用分层配色，数据区域含空白单元格均有框线，支持自动换行、冻结主体列与表头。

“导入Excel”通过主体代码和字段标识匹配当前样本。修改指标值后导入会重新计算得分；仅修改得分时按手动得分生效。模板保留隐藏的原值及手动得分标识，原样导入不会把自动计算的得分变成手动覆盖，已有手动得分可往返保留；只导入部分字段不会清除其他字段的手动得分。旧模板的“排查分”仍作为指标值兼容导入。不要修改模板表头、隐藏标识或日期，含 Excel 公式的单元格请先粘贴为值。导入只改变本次页面数据，不修改 SQLite 文件。

## 第五步最终定级

第五步“排查得分”汇总第四步该主体各项“得分”，包括公式计算结果和手动得分，不直接汇总原始指标值。先按十进制精确求和，再按 ROUND_UP 保留 4 位小数（远离 0 进位），固定显示 4 位；例如 1.23451 → 1.2346，-1.23451 → -1.2346，0.1 + 0.2 → 0.3000。最终得分为当前指标得分加上排查得分，并重新匹配最终等级。得分仍在计算或存在异常时，需等待计算完成或修正异常才能进入最终定级及导出，避免使用旧结果。以上计算仅在当前页面生效。

第五步“数据导出”生成包含评级样本、数据录入、初步评级、评级模型、等级策略、批量排查、最终定级的 Excel 文件，打开时定位到最终定级工作表。布局参考最终定级导出表样，按当前页面的样本范围和顺序导出，包含源数据、当前指标计算值、第三步手动评分、排查指标值与得分、当前页面生效的评分规则及等级区间。排查合计固定 4 位小数，等级匹配异常使用红字，所有数据格保留边框；生成过程不重新计算或写入数据库。在库定级使用第一步原定级，历史定级、调整方向及入库状态目前没有对应页面数据，保留为空。文件名包含数据日期及导出时间戳。

## 导出文件名

第二步、第四步和第五步所有可见导出工作表共用 `excel_styles.py`，按参考表样采用宋体 11 号字、灰底黑字表头、细黑色边框和白底数据区；数据录入表中的指标列继续使用蓝色区分源数据。根据中英文内容长度和合并表头调整行高，长文本自动换行。页面和导出的业务数值统一四位小数、ROUND_UP（远离零），整数和零补足四位；代码、日期、年份、序号、公式文本及说明文字保持原格式。

四位精度仅作用于展示与报表，评分引擎、页面计算、权重及等级比较继续使用原值。Python 使用 `numeric_precision.py` 的 Decimal ROUND_UP，前端使用十进制定点运算，避免浮点乘加产生额外进位。改变精度的导出数值保留原始精度批注，第二、四步导入时仅在单元格数值未变时恢复原值；已编辑的数值按新录入值生效。表头公式批注、隐藏导入标识和时间戳规则保持有效。

全部 Excel 导出文件名统一追加导出时的本地时间戳 `YYYYMMDD_HHMMSS`，保留原有数据日期。浏览器下载使用服务端给出的文件名，保存位置及重名文件处理由浏览器设置决定。

## 源码运行

Windows 推荐使用上述启动脚本。也可手动创建环境、安装依赖并运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

已安装依赖的 Python 环境可直接执行 `python app.py`。可用参数：

```powershell
python app.py --models "E:\模型文件" --port 8766
python app.py --models "E:\模型文件\河南城投2026.db"
python app.py --no-browser
powershell -File .\start.ps1 -Models "E:\模型文件" -Port 8766 -NoBrowser
```

`--models` 指定模型文件夹或单个 `.db` 文件，默认读取 `MODEL_DIRECTORY` 环境变量，未设置时使用项目 `models/`；`--port` 默认读取 `PORT` 环境变量，未设置时为 `8765`，传入 `0` 可自动选择可用端口；命令行参数优先。`--no-browser` 只启动服务，手动打开终端打印的完整页面地址。启动脚本的 `-Models` 同样接受文件夹或单个 `.db`；`-Python "C:\路径\python.exe"` 可指定首次创建虚拟环境所用的 Python。

项目以源码交付，不生成 EXE 或安装包。交付源码目录可以压缩发送；接收方根据启动清单在自己的电脑安装 Python、创建虚拟环境并安装依赖。

开发目录可执行 `python tools/prepare_delivery.py` 生成 `交付源码/`，只复制运行代码、页面资源、模型文件与启动说明；输出目录已存在时需通过 `--output` 指定新目录。交付时仅发送该目录，排除开发目录中的 `.venv`、`node_modules`、`backups`、`downloads`、`tests` 和缓存。不得沿开发目录中的目录链接复制外部依赖。
